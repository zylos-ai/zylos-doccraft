# 文档设计方法论

信息组织与视觉呈现的原则集。目标：人类读者 30 秒抓住主干、3 分钟看完主线、需要时能查到全部细节 —— 信息完整且有细节，但不逼读者线性通读。

## 目录

1. 信息组织（比视觉更重要）
2. 视觉设计原则
3. 文案原则
4. 图形化决策表
5. 常见失误清单

## 1. 信息组织（比视觉更重要）

**结论先行，倒金字塔。** 页面第一屏必须回答"读者最想问的那个问题"。TL;DR 卡 = 一句话结论 + 至多 3 个关键数字（每个数字配一句"为什么重要"）。数字比形容词有说服力：用"37% 失败来自 agent 间失调"，不用"多层架构很不可靠"。

**三层阅读深度，对应三种读者状态：**

| 层 | 承载 | 对应读者 |
|---|---|---|
| 第一层：TL;DR + 目录 chips | 结论、关键数字 | 只有 30 秒 |
| 第二层：正文可见区 | 论点、证据摘要、图 | 想看主线（3-10 分钟） |
| 第三层：`<details>` 折叠块 | 完整论证、反方观点、数据细节 | 要查证、要深读 |

分层的铁律：**折叠不等于删减**。放进折叠块的内容必须完整保留 —— 渐进披露的承诺是"信息不缩水，只是默认收起"。反方论证、诚实的局限性声明尤其不能在可视化时被顺手删掉。

**结构编码信息，不做装饰。** 编号、时间线、分区这些结构手段必须映射内容的真实属性：时间线只用于真实序列（阶段、演进路径）；状态 pill 只用于真实状态（已收敛/讨论中/待拍板）；左右分区只用于真实的二元对照。内容本身没有这个结构时不要强加 —— 并列就用卡片，不要硬编号。

**决策类文档给决策者做仪表盘。** 待拍板问题做成状态面板（qboard）：每题一卡，标题 + 状态 pill + 当前倾向。决策者一眼看到"哪些已收敛、哪些等我"。这比按章节顺序埋在正文里高效得多。

**每个 section 自包含。** 读者可能从目录 chip 直接跳进某节，该节开头要有一两句话让空降读者接得上，不依赖上一节的铺垫。

## 2. 视觉设计原则

**先看有没有既有设计系统。** 项目里已有 token/模板/组件的，沿用并只补缺口；用户明确指定的视觉方向永远优先。都没有时才启用本 skill 的默认系统（assets/template.html）。

**开工前先写设计计划**（三行即可，写在心里或 scratchpad）：
- 配色：4-6 个具名色值（底色/表面/主文/次文/accent/语义色）
- 字体：正文、显示、等宽三个角色
- 版式：一句话（如"单栏 880px，卡片网格 + 折叠块"）
然后所有具体决定从这个计划推导，不临时起意。

**一个 accent，语义色独立。** 页面只有一个装饰性主色（accent）；红黄绿等语义色（危险/进行中/完成）传达状态，不算装饰色、不与 accent 抢戏。想强调时优先用字重和留白，其次才是颜色。

**双主题都是一等公民。** token 全部定义在 `:root` 自定义属性上；`@media (prefers-color-scheme: dark)` 重定义 token；`:root[data-theme="dark"]` / `[data-theme="light"]` 再覆盖一遍（宿主的主题切换按钮要能赢过系统偏好）。组件样式只引用 token，绝不在 media query 里直接写组件样式。深色主题不是简单反色：soft 背景色要重新调（深底上用低明度色块，不是浅色块调透明）。

**中文排版三件事：** 行高 1.75-1.8（比西文松）；正文栏宽 ≤ 880px（约 40 汉字/行）；字体栈用系统 CJK（PingFang SC / Noto Sans CJK / Microsoft YaHei），不引外部字体 —— 自包含、无 CDN 依赖、无静默 fallback。数字对齐处加 `font-variant-numeric: tabular-nums`。

**布局用 gap，不用 margin 堆间距。** 同级元素间距交给 flex/grid 的 gap；宽内容（表格、图、代码）一律套 `overflow-x: auto` 容器，页面主体永不横向滚动。移动端断点一个就够（720px：多栏塌成单栏）。

**图用最便宜的手段画。** 优先级：HTML/CSS 盒子（分层图、分区图、层级条）→ 简单内嵌 SVG（拓扑、连线图，viewBox 保证响应式，颜色引用 CSS 类而非写死）→ 才考虑 canvas。SVG 里避免手写长 path，用 rect/line/circle/text 拼。图必须双主题可读（fill/stroke 走 token 类）。

**克制清单。** 不要：大 hero 区、渐变横幅、emoji 当章节标记、全文居中、每处圆角阴影、装饰性动画。一份决策文档的"美观"来自层级清晰和留白呼吸，不来自特效。

**构建卫生。** 每个非自闭合标签都闭合；属性双引号；键盘焦点有可见样式（focus-visible）；`prefers-reduced-motion` 时关掉平滑滚动；注意选择器优先级互相打架（组件类和元素选择器抢 margin/padding）。

## 3. 文案原则

- 从读者那一侧命名：说"待你拍板的问题"，不说"open issues 列表"。
- 每个折叠块的 summary 是一句"承诺"：读者点开前就知道里面有什么（"展开看完整论证 + 反方观点"，不是"更多"）。
- 状态词统一且贯穿全文：已收敛 / 部分收敛 / 讨论中 / 待拍板，不要同义词轮换。
- 图表必有标题或图注说明"看什么"；SVG 加 `role="img"` + `aria-label`。

## 4. 图形化决策表

| 内容形态 | 呈现组件 |
|---|---|
| 一句话结论 + 关键数字 | TL;DR 卡（.tldr + .facts） |
| 并列的实体/维度/选项 | 卡片网格（.cards），标题带 pill |
| 方案对比（2-3 个选项） | 并排卡片 + 各配小图，推荐项高亮边框 + "建议" 角标 |
| 真实状态集合（问题/任务） | 状态面板（.qboard + pill） |
| 真实序列（阶段/演进） | 时间线（.phases） |
| 二元对照（内/外、前/后） | 双区对照（.dmz：左右区 + 中间网关） |
| 层次结构说明 | 层级条（.layers）或分层盒子图 |
| 拓扑/连线关系 | 内嵌 SVG（rect/line + token 类） |
| 密集数据 | 表格（必须套 .tablewrap） |
| 关键洞察/警示/诚实声明 | callout（insight/threat/honest） |
| 深度论证/反方/细节 | details 折叠块 |

## 5. 常见失误清单（发布前自查）

- [ ] TL;DR 是否真的回答了读者的第一个问题（而不是文档摘要）？
- [ ] 折叠块里的内容是否完整（尤其反方论证和局限性）？
- [ ] 深色主题下逐屏过一遍：soft 色块、SVG、pill 全部可读？
- [ ] 手机宽度（≤400px）过一遍：无横向滚动、多栏已塌单栏、SVG 未溢出？
- [ ] 敏感信息扫描：内部 IP / 内部域名 / chat ID / 平台 ID / 密钥（发布即公开链接）？
- [ ] 所有外链有效？逐字版/数据源链接放了吗？
- [ ] 状态 pill 与源文档的实际状态一致？
- [ ] 页脚有版本对应关系（"本页与逐字版同步于 vX.Y"）？
